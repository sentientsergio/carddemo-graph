## 1. Goal

Model COBOL **field-level record layout** (level / name / PIC / USAGE / OCCURS / REDEFINES / parent) from copybooks (and inline `01` records) into a typed **`DataItem`** layer, so a downstream agent can derive Aurora column types from the KB instead of re-reading source. Skeleton-class: deductive parse of the data division, full provenance, no inference.

Aligns to the spec v4 deferred sketch (§Deferred extensions): "`DataItem` granularity — level, picture, usage, occurs, redefines, parent" + "BMS field ↔ symbolic-map data item — `MAPS_TO_ITEM`".

## 2. Scope

**In:**
- `DataItem` entity per data-description entry in record-layout copybooks + inline `01` records (group items + elementary items + FILLER + 88-level? — see open Q4).
- Hierarchy: parent/child via level numbers (`01 > 05 > 10 > ...`).
- Facts captured deterministically: `level`, `name`, `qualified_name`, `picture`, `usage` (DISPLAY/COMP/COMP-3/COMP-4…), `occurs` (count), `redefines` (target item name), `is_filler`, `is_group`, `parent_id`.
- A **deterministic `suggested_sql_type`** per elementary item from its PIC+USAGE (a mapping, not a commitment) — the direct KU-9 ask.

**Out (downstream / enrichment, NOT this sprint):**
- Generating the actual Aurora DDL / `CREATE TABLE`.
- OCCURS → child-table-vs-array-column *decision*; REDEFINES → which overlay is canonical. The skeleton records the *facts* (occurs N; redefines X); resolving them into a relational design is modernization analysis (downstream). **Open Q2 — confirm this boundary.**
- Byte-offset / storage-length computation (COMP-3 packing math). Possible stretch; flagged Q3.
- `MAPS_TO_ITEM` (BMS field ↔ data item) — depends on DataItem; candidate **stretch seam 2a-5**, else its own increment.

## 3. Schema additions (version bump — open Q1)

- New EntityType **`DataItem`**. Props: `level:int`, `name`, `qualified_name`, `picture`, `usage`, `occurs:int?`, `redefines:str?`, `is_filler:bool`, `is_group:bool`, `suggested_sql_type:str?` (elementary only), `parent_id`, `source_copybook_id`.
- New EdgeType **`HAS_FIELD`** (Copybook|Program record → DataItem, for the `01`-level roots) and **`CONTAINS_ITEM`** (DataItem → DataItem, parent→child). *(Or a single self-referential CONTAINS + the existing entity carrying parent_id — red-team preference?)*
- Optional later: `MAPS_TO_ITEM` (BMSField → DataItem).
- kuzu_schema.cypher: add `DataItem` node table + the rel table(s).
- **schema_version bump**: additive (no existing type/edge changes) → I read this as **minor (1.0.0 → 1.1.0)** per spec "adding new entity/edge types requires a version bump; breaking changes bump major." Confirm (Q1).

## 4. Deterministic rules (new RUL-COBOL-02x / RUL-DERIV-0xx)

Reuses the existing column-aware COBOL tokenizer (cols 8–72; the data-division walk already partially exists for FD/record tracking).
- **RUL-COBOL-021** — data-description entry: `<level> <name> [PIC <pic>] [USAGE] [OCCURS n] [REDEFINES x] [VALUE ...].` → `entity_candidate(DataItem)` + parent/child edge. Handles multi-line entries (period-terminated, like the WS-constant fix).
- **RUL-COBOL-022** — FILLER and group-vs-elementary classification (no PIC ⇒ group).
- **RUL-DERIV-0xx** — `suggested_sql_type` from PIC+USAGE (table below). Deterministic mapping.
- Hierarchy assembly in Pass 3 (parent_id via level-number stack), consistent with the resolver-is-sole-writer rule.

## 5. PIC → suggested_sql_type mapping (deterministic; the KU-9 payload)

| COBOL | suggested_sql_type |
|---|---|
| `PIC X(n)` | `CHAR(n)` (or VARCHAR(n) — red-team pref) |
| `PIC 9(n)` (unsigned int) | `NUMERIC(n)` / `BIGINT` if n≤18 |
| `PIC S9(n)` | `NUMERIC(n)` |
| `PIC S9(n)V9(m)` | `NUMERIC(n+m, m)` |
| `... COMP-3` (packed) | same numeric mapping (storage differs, logical type same) |
| `... COMP/COMP-4` (binary) | `INTEGER`/`BIGINT` by digit count |
| `88`-level (condition) | not a column — modeled as fact, no SQL type (Q4) |

CardDemo reality (grounding): 445 PIC clauses, 26 REDEFINES, 4 OCCURS, 5 COMP-3. Mostly `PIC X(n)` and display `S9(10)V99` money fields → clean NUMERIC(12,2). Low COMP-3 volume keeps packing edge-cases small.

## 6. Validation / gold

- **Structural:** every DataItem has level + (picture XOR is_group) + parent linkage; hierarchy well-formed (no orphan non-01 items); suggested_sql_type present on every elementary non-FILLER item.
- **Semantic:** every record-layout copybook (those with DEFINES_LAYOUT_FOR) has ≥1 DataItem; spot assertion that known records (ACCOUNT-RECORD = 13 items) resolve.
- **Gold (open Q5):** does Acceptance Test A gain a "Q6 — field layout for a copybook" gold entry (Reviewer-A/B trace), or is structural+semantic coverage sufficient for v2.2? Gold = human trace work → your/the sponsor's call.
